# Documentar Memoria Técnica

## Cuándo usar esta skill
- Después de una sesión exitosa de debugging de la API.
- Al cambiar la estructura de la base de datos o esquemas de tipos.
- Cuando se descubre un comportamiento indocumentado de WispHub.

## Flujo de trabajo
- [ ] Revisar `docs/wisphub_technical_memory.md`.
- [ ] Añadir nuevas entradas con fecha y descripción del problema.
- [ ] Documentar la solución (fragmentos de código o lógica).
- [ ] Verificar que no haya información obsoleta o contradictoria.

## Instrucciones
- Mantén un tono técnico pero accesible.
- Usa etiquetas de advertencia (IMPORTANT/WARNING) para errores que podrían romper la app.
- Incluye siempre el endpoint exacto y el método (PUT/PATCH/GET) involucrado.

## Recursos
- `docs/wisphub_technical_memory.md`: Documento principal de conocimiento.
